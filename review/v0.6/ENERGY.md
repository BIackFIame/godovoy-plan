# Энергия и ресурсы в 0.6.0

Измерения относятся к указанным сценариям. База сравнения — выпущенная 0.5.50, кроме отдельной проверки планировщика, где сравнивались две сборки кандидата. Данные календаря синтетические.

| Сценарий | Результат |
|---|---|
| Сетевой процесс macOS на паузе, два замера по 120 секунд | В обоих случаях 12 → 0 пробуждений. Счётчик энергии процесса зафиксировал 0,014 и 0,020 → 0 мДж. |
| Команда из 2 / 3 / 4 устройств, 200 событий, 30 секунд без изменений | Энергия процесса 5,64 → 1,86 / 22,44 → 6,23 / 16,80 → 7,48 мДж. Количество исходящих соединений 10 → 3 / 30 → 10 / 60 → 18. По одному парному измерению на размер команды. |
| Два известных устройства с включённым обменом, дополнительное изменение планировщика кандидата | За 65 секунд в двух контрольных запусках 45 и 44 пробуждения, в двух новых — по 16. Число исходящих обменов во всех четырёх запусках одинаковое, по семь. |
| Одно изменение в календаре на 1000 событий | При соединении со стороны автора 163 933 → 1 229 байт, со стороны получателя 327 612 → 1 232 байта. CPU обоих устройств 33,76 → 16,59 и 53,97 → 16,98 мс соответственно. По 24 обмена на сборку и направление. |
| Android 15 ARM64, 1000 событий, сохранение настройки паузы | CPU ядра 5,71 → 3,62 мс, пик памяти процесса 11,25 → 8,38 МиБ. Повтор той же настройки без изменений 0,83 → 0,16 мс CPU. Пять пар запусков на эмуляторе. |

На macOS энергия измерялась через счётчик процесса ri_energy_nj. LAN использовал TCP через loopback с отключённым поиском UDP. Эти измерения не охватывают энергозатраты Wi-Fi, дисплея или целого устройства. Ноль означает отсутствие приращения счётчика за период наблюдения. В серии из 80 записей команда из трёх устройств завершила обмен быстрее, а из двух и четырёх — медленнее. Общего ускорения массовых правок по этой серии установить нельзя.

Проверка серверных прав при 240 сотрудниках и восьми параллельных запросах потребовала 654 → 363 мкс CPU на запрос, p95 4,88 → 2,62 мс. На 20 сотрудниках p95 почти не изменился. При обычном интервале проверки 3 секунды и 240 индивидуальных ключах в одном прогоне процесс потратил 1267 → 979 мс CPU на 1200 проверок, p95 при этом вырос с 8,22 до 11,93 мс. Содержимое файла прав сервер читает при каждом обращении.
