# Перевыпуск доступа к календарю

Если сотрудник потерял ноутбук или больше не работает с командой, на доверенном компьютере откройте **Синхронизация → Доступ к календарю**. Отметьте одно или несколько устройств, нажмите **Отозвать доступ устройств…**, проверьте список и подтвердите **Отозвать доступ**. Сверяйте ID компьютера, особенно если у двух сотрудников одинаковое имя. Собственный ID виден в этом разделе на каждом компьютере. Программа сохранит историю и назначения, сменит общий ключ и добавит выбранные ID в список отозванных. Обновлённое пространство откажет им в новом приглашении.

Компьютер, впервые перевыпустивший ключ, становится управляющим. Для первого перевыпуска выберите одну доверенную машину с актуальным календарём. В дальнейшем новые приглашения, отзыв устройств и смена ключа выполняются только на ней. Остальные сотрудники видят имя и ID управляющего компьютера в окне синхронизации. Для замены ключа без блокировки конкретного устройства оставьте список выбора пустым и нажмите **Перевыпустить доступ…**. Для событий и истории устройство сохраняет прежний ID.


У каждого коллеги, который сохраняет доступ, в этом же разделе есть кнопка **Скопировать запрос устройства**. Управляющий проверяет, от кого пришёл запрос, и передаёт коллеге созданный для него код. Он вводит код в **Новый код приглашения** и нажимает **Подключиться по новому коду**, пока приложение остаётся открытым. При необходимости можно указать IPv4-адрес приглашающего компьютера. Коллега сохраняет свою личность в календаре, назначения и локальные правки. Его профиль принимает только более новое поколение ключа того же календаря. После успешного подключения компьютеры обмениваются объединённым календарём.

Перевыпуск заменяет общий ключ пространства. Остальные участники, включая потерянный компьютер, остаются в прежней группе до получения адресного приглашения. Прежние устройства всё ещё могут обмениваться уже известными им данными между собой. Передавайте новые приглашения только доверенным сотрудникам. Устройство без нового ключа не получит будущие изменения через сеть и не расшифрует новые файлы `.yrplan`. Имена участников сохраняются в календаре для истории и назначений. На управляющем компьютере раздел «Участники» показывает для каждого устройства, ожидает ли оно подключения, принят ли его запрос или отозван доступ. Статус «запрос принят» означает, что управляющий обработал обращение. При обрыве сети сотрудник мог не получить ответ. Содержимое уже скопированного календаря остаётся у владельца копии.

При операции приложение приостанавливает прежнюю сеть, пишет календарь, сохранённые черновики и отметки напоминаний в отдельный закрытый каталог и только затем публикует указатель на него. Настройки интеграций в новом профиле потребуется включить и настроить заново. Старая копия и её резервные файлы сохраняются в прежнем каталоге. При обычном запуске программа выбирает актуальное поколение. Для восстановления используйте резервные копии, созданные после перевыпуска в активной копии. Программа сохраняет метки 128 предыдущих поколений. Повторное подключение после пропущенных перевыпусков возможно в пределах этой истории. Если две группы независимо перевыпустили один ключ, они образовали отдельные ветви. Автоматическое переподключение между такими ветвями блокируется, чтобы одна группа случайно не отдала другой свои новые данные.

Остальным сотрудникам следует приостановить обмен с прежней группой с момента решения отозвать доступ. До перехода на новое поколение изменения, внесённые в старую группу, остаются доступны её участникам. При вводе нового кода приложение автоматически ставит прежний обмен на паузу. Если подготовка или подключение прерваны, проверьте причину в окне синхронизации и повторите действие.


## Управляющий компьютер и резервные копии

Сразу создайте резервную копию активного поколения на управляющем компьютере. Храните защищённую копию его профиля с резервными файлами и сведениями об их происхождении. При потере управляющего компьютера сначала восстановите его профиль на доверенной машине и перевыпустите доступ. Если потерянный и восстановленный компьютеры содержат одну и ту же копию, это один ID. Смените ключ в восстановленной копии и заново пригласите доверенных коллег. При недоступности профиля управляющего и его защищённой копии потребуется создать новое пространство и заново подключить сотрудников. Предыдущие копии остаются доступны их владельцам.

Отзыв относится к ID профиля. Чистая установка с новым ID требует нового приглашения от управляющего. Приложение не устанавливает личность человека по отображаемому имени и не умеет идентифицировать физический ноутбук с переустановленной ОС. Проверяйте запросы по известному каналу связи. Управляющие права ограничивают действия штатного приложения. Все допущенные устройства получают общий ключ и календарь, поэтому в состав команды включайте только доверенных участников.

В прямом LAN-обмене соединение подтверждает владение действующим общим ключом. Идентификатор отправителя передаётся внутри защищённого соединения. Отдельной подписи устройства на каждой правке календаря нет. Если сотрудник должен видеть только свои назначения, предоставьте ему персональный серверный доступ с ограничением по назначениям.
