# Годовой план 0.5 — проверка выпуска

## Отметки, уведомления и интеграции в 0.5.33

Открытие события из списка напоминаний и запись отметки разделены. Рабочий поток принимает отдельные и массовые отметки, объединяет быстрые нажатия и исключает повторную запись той же отметки. Срок проверяется по актуальному календарю. Отметка с прежней датой не скрывает напоминание о новом сроке. При закрытии окна приложение дожидается записи.

Локальный API меняет состояние и токены в рабочем потоке. Выключение сначала сохраняет запрет запросов, затем закрывает соединения. Если запись настройки не удалась, слушатель и токены сохраняются. Обычный выход закрывает слушатель и сохраняет предпочтение запуска на будущее.

В системное уведомление передаётся только стандартное приглашение открыть список. Календарные данные остаются внутри окна приложения. Для профиля Windows продолжают действовать права файловой системы. Проверки под второй учётной записью Windows в этой среде недоступны. [Модель доступа Windows](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)

В нативном окне macOS открыли список из календаря, отметили одну запись, перешли в карточку второго события, вернулись в список и отметили остальные. Окно дождалось двух записей при закрытии. После запуска все четыре отметки остались на диске. Для API начали локальную загрузку и нажали «Выключить» до завершения запроса. Окно реагировало, порт освободился, незавершённая загрузка осталась вне календаря. В обеих проверках использовались временный профиль и задержка в одну секунду. Системный текст проверялся без отправки уведомлений на рабочий стол. Прошли 117 Rust-тестов и Clippy.

## Память задач и диагностика моста в 0.5.32

Кэш задач и напоминаний определяет версию профиля и отметок по слабым ссылкам. После публикации нового профиля прежний снимок может освободиться до следующего кадра. Строки и напоминания пересчитываются при смене данных или даты.

Три парных прогона на Mac использовали один сценарий с 1 800 событиями, длинными заметками и 24 полными обновлениями. Перед обновлением кэша в 0.5.31 оставались живы 1 800 объектов прежних событий, в 0.5.32 — ни одного. Живые выделения Rust в этой точке уменьшились с 18,97 до 9,71 МиБ (48,8%). После обновления кэша обе сборки показывали 9,71 МиБ. Замер не включает системный RSS, оконную графику или продолжительную работу на Windows.

Мост читает файл сопоставления через буфер и проверяет фактический предел в 64 КиБ. Ошибка разбора показывает только позицию. Проверка с синтетическими значениями в имени поля и в строковом значении подтвердила, что они не попадают в вывод командной строки.

## Фоновое восстановление отметок в 0.5.31

Восстановление выполняется в рабочем потоке. Оно блокирует запись только в файл отметок. Календарь можно читать и изменять во время восстановления. Блокировка профиля остаётся в силе до завершения операции. Простое закрытие окна ожидает результат, при отказе окно остаётся открытым.

Сравнение нативных окон с одинаковой имитированной задержкой в 1,4 с показало, что 0.5.30 задерживал следующий кадр до окончания операции. В 0.5.31 окно обрабатывало кадры во время задержки. Отдельный тест остановил копирование в хранилище, записал календарь, проверил защиту от повторного открытия профиля и убедился, что параллельная запись отметок получила отказ. Тесты сохранности оригинала из 0.5.30 по-прежнему проходят.

## Восстановление отметок напоминаний в 0.5.30

При недоступных жёстких ссылках исходный файл отметок сохраняется отдельной побайтовой копией с ограничением в 32 МиБ. Новый файл публикуется после успешного архивирования. Путь архива создаётся эксклюзивно. При ошибке архивирования исходный файл и предупреждение остаются прежними.

Тесты с имитацией файловой системы без жёстких ссылок проверили байты повреждённого оригинала, запись пустых отметок, обновление интерфейса через снимок хранилища и сохранность слишком большого файла. Две целевые мутации подтвердили, что тесты выявляют отключение запасного копирования и преждевременную замену оригинала. Проверка физического носителя в этот прогон не входила.

## Завершение файлового обмена в 0.5.29

При обычном закрытии окна интерфейс продолжает обрабатывать события, пока файловая операция заканчивается. После ошибки обмена окно остаётся открытым. Если есть несохранённые черновики, после успешного обмена открывается штатное подтверждение выхода.

Запасной способ экспорта освобождает временную копию до создания конечного файла. Он сохраняет существующий файл при совпадении имени. При прерванной записи приложение сообщает о неполном файле, который можно убрать вручную. Приём проверяет целостность пакета перед слиянием. Проверка с имитацией полного диска покрывает этот отказ без физического носителя.

На macOS «Показать в папке» дожидается завершения системного процесса в рабочем потоке и показывает ошибку, если Finder не смог открыть путь. Регрессия проверяется на перемещённом файле.

Нативный прогон с временным профилем подтвердил ожидание при закрытии, автоматический выход после записи и возврат к открытому окну при конфликте имени. Существующий файл сохранился побайтно. Прошли 104 Rust-теста, Clippy и шесть целевых мутаций файлового обмена в отдельной копии. Шестая проверила освобождение временной копии при запасной записи.

## Файловый обмен в 0.5.28

Файл `.yrplan` содержит только календарь и идентификаторы команды и источника. Ключ файла выводится через ключевой BLAKE2s с отдельной меткой формата. XChaCha20-Poly1305 использует случайный 24-байтовый nonce при каждом экспорте. Приложение проверяет подлинность файла до распаковки, ограничивает размер файла и открытого текста и объединяет записи одной транзакцией. Общий секрет подтверждает принадлежность к команде. Идентификатор автора в пакете не является цифровой подписью.

Два временных профиля сошлись после экспорта и импорта в обе стороны. Проверены дневник, отметки, снятие отметки, удаления, повтор без записи, чужой файл, неправильный тег аутентификации, обрезка, превышение границы распаковки и отказ перезаписи существующего пути. Физические носители, AirDrop, Bluetooth и кабель в этот прогон не входили.

В отдельной копии тесты выявили пять искусственных поломок. Это повтор nonce, пропуск ошибки тега, разрешение перезаписи, принятие хвоста после сжатого потока и снятие лимита распаковки. Контрольный прогон без изменений прошёл. Это проверка конкретных инвариантов файлового обмена.

## Результат работы моста в 0.5.25

Итог прохода передаётся в отдельном сеансе Noise с лимитом открытого текста 1 КиБ. Подтверждение означает запись в журнал или публикацию в памяти при недоступном файле. Регрессионные тесты проверили отзыв токена после рукопожатия, недопустимые счётчики, неопределённость при пропавшем ответе, повторное открытие журнала и побайтно прежние календарь и файл пачек при приёме сводки.

## Журнал локального импорта в 0.5.24

Тесты провели успешный, повторный и отклонённый импорт через HTTP и успешный импорт через защищённый канал моста. Принятые пачки получили счётчики, отказы — категории из перечисления. Запросы с недействующим токеном не меняли журнал, в том числе после смены токена во время запроса. В файле истории отсутствуют тестовые токены, внешние ID и содержимое событий. В календаре и его копии история не сохраняется.

При отказе записи файла истории импорт ответил успешно и сохранил календарь. Пока запись была недоступна, результат был виден из памяти с предупреждением. Следующая запись после устранения сбоя сохранила журнал. Повреждённый или чужой журнал остался побайтно прежним при открытии профиля. Отдельно проверены лимит 32 источников и восстановление истории после повторного открытия.

## Перенос импорта в 0.5.23

Два временных профиля обменялись по штатному протоколу на loopback. До обновления тесты воспроизвели две ошибки. Запись и отметка из старого года перестали отображаться после переноса, а конкурирующие переносы оставили две карточки с одним UUID.

В 0.5.23 прошли переносы в обе стороны, правки офлайн, снятие отметки, повтор импорта, повторное открытие профиля и конкурирующие даты. Годовые записи ежегодного события остались отдельными. Приложение по-прежнему читает прежние поля профиля, а два клиента с разными версиями могут показывать старую историю по-разному. Для одинаковой выдачи обновите оба клиента.

Отдельно запустили архивные macOS-бинарники 0.5.22 и 0.5.23 с временными профилями. После обычного переноса через API оба получили одинаковый сохранённый календарь. Конфликт дат и поздние записи проверяли двумя профилями новой версии.

## Проверка интеграций в 0.5.21

- После подтверждения HTTP-заголовков клиент оставил тело импорта незавершённым. Затем сменили токен или выключили API в профиле и отправили тело. Сервер вернул соответственно 401 и 503, и календарь на диске совпал с текущим состоянием профиля без импортированных событий.
- Те же изменения проверены после рукопожатия штатного зашифрованного соединения моста. Календарь остался пустым.
- После отключения и остановки сервера незавершённое HTTP-соединение закрылось. Порт сразу удалось занять вновь. Все проверки прошли на loopback с отдельными временными профилями.

## Функции

- Обзор на 30, 60 и 90 дней сортирует даты старта подготовки, незавершённые сроки и события по неделям. Можно выбрать ответственного или события без ответственного. Тест покрывает события, подготовка к которым начинается в предыдущем году.
- Напоминания возникают с начала подготовки, за день до срока незавершённого пункта и при открытом просроченном пункте. Список пересчитывается из календаря. Прочтение записывается отдельно от календаря. Нативный прогон на macOS воспроизвёл отказ системного показа, нажатие «Отметить все прочитанными» и повторный запуск. Системное уведомление в этом прогоне было заменено тестовым обработчиком.
- Автозапуск основного профиля включается явно. На macOS запись создаётся в пользовательских LaunchAgents, на Windows в пользовательском ключе Run. Проверена сериализация аргументов macOS, а Windows-код собран для трёх архитектур. Фактический вход в систему с автозапуском не проверялся.
- Прошли 24 Rust-теста, проверка форматирования и Clippy с запретом предупреждений.

## Безопасность

Статический аудит 0.4 охватил собственные исходники настольного приложения, профиля, LAN, API и моста, а также конфигурацию, тесты и документацию. Три независимых прохода проверили границы. В [отчёте исходной версии](BASELINE-AUDIT.md) четыре находки. Исправления в 0.5 проверялись отдельно.

| Область | В 0.5 |
| --- | --- |
| Подлинность локального API | Штатный мост проверяет общий секрет через Noise до отправки пакета и не переключается на открытый HTTP. Мосту 0.5 требуется приложение 0.5 или новее. |
| Отзыв API-токена | Запись перепроверяет токен под блокировкой транзакции. Принятый ранее запрос не может записать данные по уже отозванному токену. |
| LAN-обнаружение | Ручной и встроенный в код адреса идут перед результатами автопоиска. Введено ограничение записей обнаружения от одного IP и пауза между повторными попытками. |
| Переполнение реплики | Отказ слияния отражается в статусе, прежние копии сохраняются. Сборка истории удалений ещё не реализована. |
| Устаревшая резервная копия | Новая правка получает уникальный идентификатор даже при повторном номере ревизии после восстановления. Формат, который читают версии 0.4, сохранён. |
| Локальные файлы | Приложение проверяет тип файлов профиля, допустимость загруженного календаря и на macOS права каталога. Собственный код трёх Rust-целей запрещает `unsafe`. |

RustSec на снимке базы от 22 ноября 2026 года не сообщил известных уязвимостей в `Cargo.lock`. База отмечает прекращение сопровождения `chrono` и трёх пакетов в ветке зависимостей Linux. [Проверка chrono](https://rustsec.org/advisories/RUSTSEC-2026-0543)

Участники пространства всё ещё доверяют друг другу через общий ключ. Индивидуальный отзыв устройства и подписи автора каждого изменения отсутствуют. Токен импорта даёт доступ ко всем источникам профиля. Для прямых HTTP-клиентов сохраняется loopback API с Bearer-токеном. Windows ACL зависят от профиля пользователя ОС. Мост запускается отдельным процессом с правами пользователя ОС.

Утилита macOS `leaks --atExit` сообщила 0 утечек в тестах повторной обработки HTTP и трёх сценариях LAN. Утилита отметила ограничения чтения памяти тестовых процессов. Длительный прогон GUI и проверка памяти в Windows в этот замер не входили.

## Нагрузка и сеть

| Замер в оптимизированной сборке на Mac | Результат |
| --- | ---: |

| Первичная репликация того же календаря, профиль 2,98 МБ | 113 мс |

Сетевые замеры сделаны через loopback. Байты синхронизации указаны после рукопожатия Noise, без TCP/IP. При изменениях передаётся сжатый снимок, а при совпадении только управляющие сообщения. Объём профиля ограничен 8 МиБ и 2 000 планами с историей удалений. Эти измерения не задают гарантированную пропускную способность для Wi-Fi, VPN и старых устройств.

## Совместимость

Собраны универсальная macOS-версия и Windows-версии x86, x64 и ARM64. Текущие цели Rust для Windows указывают Windows 10 и новее. Windows XP, Vista, 7 и 8.x не входят в заявленную совместимость этих сборок. Windows-бинарники проверены как исполняемые файлы нужной архитектуры. Запуск в Windows, обмен Windows ↔ Mac и замеры на двадцатилетнем оборудовании не подтверждены. [Официальная таблица целей Rust](https://doc.rust-lang.org/rustc/platform-support.html)
