# Права и потребление ресурсов в 0.5.48

Проверка выполнена 25 ноября 2026 года. Исходная версия — 0.5.47, коммит `d75662f`. Использованы синтетические календари, локальная сеть и тестовые ключи. Конфигурация конкретного предприятия в проверку не входила.

## Где действуют права

| Точка входа | Что проверено | Что учитывать ИТ |
|---|---|---|
| Веб-календарь и REST | Видимость назначений, чтение без записи, политика свободного текста и разрешение удалённого входа. Сервер проверяет текущие права при обращении. | Офисный и внешний входы публикуются согласно [руководству](../../SERVER.md). |
| MCP | Ключ помощника связан с личным ключом. Учитываются владелец события в конкретном году, переназначение, права на запись, офисный вход и отзыв родительского ключа. | За пределами приложения уже полученную информацию может сохранить клиент или провайдер модели. |
| Панель ИТ, резерв и восстановление | Панель управления использует отдельный доступ. Резерв учитывает установленный ИТ срок. Восстановление в новый каталог отзывает старые ключи. | Автономная работа во время перезапуска основного сервера требует работающего резервного узла и доступа к актуальному общему тому. |
| Настольный мост, локальная сеть и файлы обмена | Проверены защищённый локальный API, устройство, подписи, привязка к группе и права файлов профиля. Пройден штатный набор тестов LAN и импорта. | Автономный участник получает локальную копию. Отзыв доступа к серверу не удаляет прежнюю выгрузку. Управлять устройствами и ключами группы нужно отдельно. |
| Телефоны | В Android манифест объявляет сетевой доступ, уведомления и получение события загрузки для напоминаний. Профиль исключён из резервного копирования приложения. В iOS объявлена цель доступа к локальной сети. Обмен файлами идёт через системный выбор документа. | Разрешения ОС, экран блокировки, системные уведомления и внешний файловый провайдер зависят от устройства. |

## Исправления

* В 0.5.47 каждый корректно оформленный неподтверждённый ключ мог занимать общий замок и вызывать синхронную запись в журнал. В 0.5.48 неизвестные ключи проходят ограничение до обращения к хранилищу. Сервер хранит до 512 отпечатков ранее подтверждённых ключей. Даже для знакомого ключа каждый запрос проходит действующую авторизацию. Отзыв продолжает действовать, когда места для проверки новых ключей заняты. Для нового подключения в такой момент предусмотрен HTTP 429 и повтор через секунду.
* Сервер регистрирует повторные неподтверждённые ключи выборочно, до одной записи в минуту на процесс. Журнал календаря не является полным счётчиком сетевых попыток. Для статистики входов можно собирать коды ответов на прокси с исключением заголовка Authorization. Ограничение доступа и учёт действий с подтверждённым ключом продолжают действовать.
* При уходе в фон команда паузы мобильного P2P раньше могла ждать медленный системный файловый провайдер. В 0.5.48 работа с ним вынесена из очереди команд ядра. Ядро обрабатывает свои команды последовательно. Ядро запускает повторно открытый в фоне профиль с уже включённой паузой. При изменении настройки синхронизации транспорт ждёт возврата на экран.
* В основном Cargo.lock зависимость cookie обновлена до 0.18.3. Затронутый PrivateJar отсутствовал в графе сборки приложения. Повторная проверка cargo-audit с проверкой отозванных версий охватила 477 пакетов основного проекта и 93 пакета мобильного ядра. На ревизии RustSec `b9b8a3c2` известных уязвимостей и отозванных версий в обоих файлах не обнаружено. Сохраняются предупреждения о сопровождении chrono, а также zbus_names, zvariant и zvariant_derive в основном проекте. [Описание исправления cookie](https://rustsec.org/advisories/RUSTSEC-2026-0594.html)

## Замеры

Серверы из двух опубликованных архивов macOS universal запускались на Apple Silicon. На одном календаре выполнены пять пар запусков, версии чередовались. В новом процессе для каждого замера выполнены один прогрев и 12 авторизованных GET /v1/state. В таблице приведены медианы по пяти процессам. RSS — пиковая резидентная память процесса, включая подготовку ответа. Канонический JSON обеих версий совпал, размер большого ответа составил 1 638 357 байт. Во всех событиях было по восемь задач, каждое четвёртое назначено вошедшему сотруднику.

| Сценарий | 0.5.47 | 0.5.48 |
|---|---:|---:|
| 1 000 событий, время ответа | 28,84 мс | 14,65 мс |
| 1 000 событий, пиковый RSS | 31,22 МиБ | 13,72 МиБ |
| 20 событий, время ответа | 6,08 мс | 5,24 мс |
| 20 событий, пиковый RSS | 9,00 МиБ | 8,56 МиБ |
| Отзыв через CLI во время копирования журнала 64 МиБ | 192,60 мс | 25,85 мс |
| Проверка модели из 1 000 событий по 20 задач | 825,9 мкс | 445,1 мкс |

* Ответ календаря формируется из типизированных представлений. Поля и элементы чек-листа сериализуются без промежуточного дерева JSON на каждое событие.
* В отдельном непрерывном прогоне готового сервера выполнено 500 чтений большого календаря. Снимки RSS через каждые 25 запросов с 125-го до 500-го показали 15,75 МиБ. Проверен один процесс, один активный читатель и один тип нагрузки. Длительная работа интерфейса и параллельные записи требуют отдельных измерений.
* При проверке самой модели использованы девять пар измерений. Для 20 задач на событие число выделений памяти в куче за проверку снизилось с 3 329 до нуля. Этот показатель относится к функции проверки модели.
* Для замера отзыва использованы пять пар запусков. Команда отзывала действующий ключ в процессе записи резервной копии. Все десять копий успешно прошли пробное восстановление. Зафиксированные префиксы до 64 месячных журналов копируются после освобождения общего замка. Остальные журналы по-прежнему включаются в копию под замком. До записи копии в памяти могут временно находиться календарь, ACL и маркеры, суммарно около 9 МиБ при максимальном заполнении.

Штатные наборы Rust прошли полностью. В настольной конфигурации выполнено 198 тестов, в серверной — 122, в мобильном ядре — 6. Конфигурации частично выполняют одинаковые тесты. Clippy с отклонением предупреждений прошёл для приложения и мобильного ядра.

## Оставшиеся возможности

Веб-календарь периодически перечитывает открытый год целиком, даже если данные не изменились. Следующий кандидат для снижения сетевого трафика — условное чтение по ревизии календаря с обязательной проверкой ключа, текущих назначений, даты и режима защиты до любого ответа о неизменности. Для настольного P2P имеет смысл отдельно измерить энергопотребление простоя и заменить опрос TCP каждые 40 мс ожиданием события с пробуждением при остановке.

Пакеты Linux x64 и ARM64 прошли проверки в виртуальных машинах. Universal macOS проверен по структуре и подписи и запущен на Apple Silicon. Windows x64 проверен по структуре PE и импортам. Нативный запуск Windows и Intel macOS в этот прогон не входил. Android APK подписан тестовым ключом. Для iOS поставляются проект Xcode и собранные библиотеки Rust для устройства и симулятора. Проверка и подпись приложения на устройстве требуют настроенной среды Apple.
