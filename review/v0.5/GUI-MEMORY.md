# Удержание памяти экраном «Обзор» в 0.5.11

В 0.5.10 кэш «Обзора» держал сильную ссылку на снимок профиля. Когда пользователь переходил на другой экран и календарь обновлялся, прежние данные могли оставаться в памяти до повторного открытия «Обзора». В 0.5.11 кэш сравнивает снимки по слабой ссылке. Строки «Обзора» по-прежнему пересчитываются при изменении снимка, даты, горизонта или ответственного.

Две диагностические сборки отрисовали нативное окно на macOS с одинаковым временным профилем из 1 950 событий и 23 400 пунктов чек-листов. После открытия «Обзора» проверка перешла в «Календарь» и сохранила изменения во всех событиях одной транзакцией. На отрисовке «Календаря» проверка измерила число живых объектов из старого снимка. После возврата обе сборки построили 27 300 строк по новому снимку. Изменения проверены в сохранённом JSON.

| Ревизия | Старый снимок жив на экране «Календарь» | Старые объекты событий в памяти | Живые выделения Rust на экране «Календарь», МиБ |
| --- | --- | ---: | ---: |
| 0.5.10 | Да | 1 950 | 16,69 |
| С исправлением 0.5.11 | Нет | 0 | 11,46 |

Время жизни объектов измерили через счётчики сильных ссылок. Объём живых выделений Rust измерили в отдельном парном прогоне с диагностической обёрткой стандартного аллокатора. При первом открытии «Обзора» обе сборки показали 10,92 МиБ. После обновления календаря разница составила 5,23 МиБ.

В трёх запусках каждой сборки системный RSS на экране «Календарь» составил 113,81–114,47 МиБ для 0.5.10 и 113,26–115,34 МиБ с исправлением. Диапазоны пересекаются. Эти замеры занимали около двух секунд на экран и не охватывают длительную работу GUI.

В отдельном прогоне участник в другом процессе добавил запись в дневник и отметил выполненный пункт. Нативное окно получило и сохранило обе правки через P2P по loopback, пока был открыт «Календарь». Старый снимок уже освободился. При возврате в «Обзор» по обновлённому календарю отобразилось 25 349 вместо 25 350 строк. Обе правки проверены в сохранённом профиле.
