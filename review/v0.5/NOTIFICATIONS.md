# Проверка уведомлений и автозапуска в 0.5.7

- В закреплённой версии `notify-rust` вызов `show()` для устаревшего macOS-бэкенда создавал дескриптор, не отправляя уведомление. Для macOS подключён `UNUserNotificationCenter`. Пользователь может проверить системную доставку из раздела **Напоминания**. На macOS разрешение запрашивается только после нажатия этой кнопки. [Документация библиотеки](https://docs.rs/notify-rust/latest/notify_rust/) · [API Центра уведомлений Apple](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter)
- Если обычная отправка не удалась, напоминание остаётся пригодным к повторной отправке. Пауза увеличивается до 1, 5 и 15 минут. Успешный запрос к Центру уведомлений и прочтение внутри календаря учитываются отдельно.
- Если приложение переместили, старую запись автозапуска можно обновить или отключить. Повторный процесс с флагом `--at-login` для занятого профиля завершается без окна. При обычном ручном запуске причина по-прежнему видна.

На macOS запустили приложение с временным профилем и отдельным идентификатором. Центр уведомлений отказал в разрешении, интерфейс показал ошибку и подсказку. Успешное появление баннера после разрешения остаётся открытым. Тестовое приложение снято с регистрации, настройки основного приложения и реальный автозапуск не меняли. [Экран после отказа macOS](notification-permission.png)

Все 41 тест Rust прошли. Проверены повторная отправка, отдельный статус прочтения, перенос записи автозапуска в тестовой папке и начало подготовки в декабре для январского события. В отдельном процессе проверено, что повторный запуск при входе завершился без окна и без изменения файла профиля. Вход в реальную сессию с автозапуском и запуск в Windows остаются открытыми. Сборки для macOS и Windows x86, x64, ARM64 подготовлены.
