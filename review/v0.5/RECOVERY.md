# Восстановление при запуске «Годового плана» 0.5.5

При запуске из Finder или Проводника сообщение из консоли недоступно большинству сотрудников. В 0.5.5 ошибки открытия профиля показываются в окне приложения. В нём видны причина, путь к папке профиля и **Повторить попытку**. Путь можно скопировать. [Экран восстановления](recovery.png)

Проверено на macOS в нативном окне с тестовым профилем:

1. Запуск с повреждённым `calendar.json` показывает причину и сохраняет исходные байты.
2. После перемещения повреждённого файла **Повторить попытку** показывает, что файл отсутствует. Новый профиль при этом не создаётся.
3. Когда в папку возвращается исправная копия, повторная попытка открывает календарь в том же окне. Копия и отдельно сохранённый повреждённый файл сохраняют свои байты.

35 тестов Rust прошли на macOS при повторном прогоне. Проверки отдельно подтверждают сохранение слишком большого календаря и блокировку второго экземпляра. Один тест совместимости со старым протоколом дал `Invalid argument` при первом прогоне параллельно со сборкой, затем прошёл в общем наборе и пять раз отдельно. Причину этого единичного сбоя ещё предстоит установить. `cargo fmt --check` и Clippy с запретом предупреждений прошли.

Подготовлены кросс-сборки Windows x86, x64 и ARM64. Запуск в Windows остаётся открытым. Резервную копию для этого сценария пока восстанавливают вручную.
