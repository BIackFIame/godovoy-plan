# Ёмкость и отзывчивость в 0.5.2

## Предельный профиль в 0.5.26

В 0.5.25 сохранение паузы или восстановление копии размером ровно 8 МиБ могло превысить предел из-за служебных полей. Для локального профиля выделены дополнительные 64 КиБ. Размер сетевого сообщения остался прежним. Приложение проверяет также размер полной формы приглашения.

Тесты восстановили копию размером ровно 8 МиБ после исчезновения рабочего файла и при открытом профиле с API и 256 регистрациями устройств. Проверены перезапуск с паузой, сохранение прежних байтов и отказ записи при превышении сетевого предела. При отказе диска пауза вступает в силу в текущем процессе, приложение сообщает, что её не удалось сохранить. После восстановления обмен принимает уже известные высокие ревизии и прежним образом отклоняет чрезмерный скачок.

В нативном окне macOS при 1040 × 630 проверили кнопку создания, сочетание клавиш, создание по образцу и действие в пустом году на профиле из 2 000 записей. После Escape фокус вернулся к исходной кнопке. Восстановленный черновик сохранился, а изменение существующего события записалось. При заполнении в байтах редактор показал предел обмена и сохранил введённый текст.

## Заполнение профиля

Пункт «Синхронизация» показывает размер сохранённого файла и число записей. История удалений входит в число записей, поскольку она нужна для обмена с офлайн-устройствами. Отметка о лимите появляется при заполнении на 90%. Интеграции с основным токеном могут получить те же четыре показателя через `GET /v1/capacity`.

Пределы составляют 2 000 записей и 8 МиБ для `calendar.json`. Превышение любого предела отклоняет запись атомарно. Новый пакет импорта проверяется до копирования профиля на число новых записей. Изменения уже существующих записей остаются возможны, если не превышен лимит файла. Автоматической очистки истории в этой версии нет.

В LAN-тесте две реплики получили по 1 100 разных записей без связи. После возобновления обмена они попытались объединиться, обе копии сохранились, а устройство, отклонившее объединение, сообщило точную причину. Отдельные тесты покрывают переполнение в байтах, отказ смешанной пачки импорта и обновление существующей записи при заполненном лимите записей.

## Чтение во время записи

Интерфейс, LAN и HTTP-чтение получают опубликованный снимок. Он меняется после успешной записи и замены файла. Операции записи API выполняются по одной в рабочем потоке, а авторизация проверяется повторно непосредственно перед записью.

На Mac использовали синтетический профиль с 1 800 событиями, 21 600 пунктами и размером файла 2,998 МБ. В каждой серии из 31 замера запускали чтение, пока другой поток удерживал блокировку для реального изменения дневника и атомарной записи профиля.

| Путь чтения снимка | Медиана | p95 |
| --- | ---: | ---: |
| Через блокировку записи | 20,05 мс | 45,19 мс |
| Через опубликованный снимок | < 0,01 мс | < 0,01 мс |

Замер включает получение снимка. В него не входят рендеринг окна, обработка HTTP и передача по сети. Результаты относятся к использованному Mac и тестовым данным. Запуск в Windows в этом прогоне не выполнялся.
