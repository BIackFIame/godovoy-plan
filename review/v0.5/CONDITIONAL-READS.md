# Расход ресурсов при обновлении открытого календаря

Сервер 0.5.49 передаёт сведения о событиях повторно, когда они изменились для вошедшего сотрудника. При неизменном представлении сервер отвечает HTTP 304. Браузер сохраняет открытый список, прокрутку и фокус. При очередном обновлении года этот же запрос подтверждает права доступа. Во время редактирования форму не прерывает фоновое обновление, а проверка сеанса продолжается.

## Измерения на macOS с Apple Silicon

Исполняемые файлы взяты из универсальных архивов 0.5.48 и 0.5.49. Обе версии обслуживали один синтетический календарь на loopback. Использованы календари на 20 и 1 000 событий, по восемь пунктов чек-листа на событие. Каждое четвёртое событие назначено вошедшему сотруднику. Для каждого размера выполнены пять пар запусков с чередованием версий. В каждом процессе измерялись первое полное чтение и 20 повторных. Проверялись содержимое первого ответа, обновление после добавления события и последующее неизменное чтение.

| Повторный GET открытого года | 0.5.48 | 0.5.49 |
|---|---:|---:|
| 1 000 событий, HTTP-ответ | 1 638 909 байт | 600 байт |
| 1 000 событий, время ответа | 14,10 мс | 6,77 мс |
| 1 000 событий, процессорное время сервера | 7,68 мс | 1,44 мс |
| 20 событий, HTTP-ответ | 33 522 байт | 600 байт |
| 20 событий, время ответа | 16,50 мс | 17,78 мс |
| 20 событий, процессорное время сервера | 0,73 мс | 0,55 мс |

Размер HTTP-ответа измерен на соединении клиента, с заголовками, без расходов TCP и TLS. В тесте запрос вырос с 208 до 291 байта из-за передачи метки. Время ответа и процессорное время процесса сервера измерены отдельно. Для небольшого календаря выигрыш в миллисекундах ограничивает стоимость остальных операций, включая обязательную запись в журнал.

В отдельном замере памяти запускали по три процесса для каждого сценария. В каждом процессе выполнены одно полное и 200 повторных чтений большого календаря. Медиана пикового RSS составила **11,92 МиБ** для версии 0.5.48, **12,94 МиБ** для условных чтений 0.5.49 и **13,94 МиБ** для полных чтений 0.5.49. Между 100-м и 201-м чтением условного запроса изменения RSS в трёх процессах составили 0, 0,016 и 0 МиБ. На этой нагрузке выигрыш в сетевом трафике и CPU сопровождался увеличением пика памяти примерно на 1 МиБ относительно предыдущей версии. Это измерения одного локального читателя на одной платформе.

## Проверки корректности

- На каждом чтении годового представления сервер проверяет ключ, политику доступа, текущую локальную дату и резервное окно под той же блокировкой, что и изменения прав. Ошибка регистрации в журнале закрывает чтение.
- На стороне сервера сохраняются до 128 пар отпечатков и меток. Сервер сравнивает фактическое содержимое хранилища и параметры представления. При их изменении пересчитывает доступный сотруднику результат. Метка, передаваемая клиенту, зависит от его ключа и видимого ответа. Изменение чужого события при персональной области доступа сохраняет прежнюю метку, если для сотрудника ничего не изменилось.
- Протестированы переход на следующий день и год, изменение события, смена прав, отзыв ключа, закрытие резервного окна, слабые и составные HTTP-метки, смена вкладки и ответ на устаревший запрос. Тесты браузера включали ошибку сервера, скрытие рабочего пространства и потерю подтверждения доступа.
- При отключении интернета офисный доступ продолжает работать по локальной сети в соответствии с настройками узла. Обновление открытого года требует связи с этим узлом. [Развёртывание](../../SERVER.md) · [Контракт для интеграций](../../ONLINE-API.md#повторное-чтение-открытого-года)

Полные наборы тестов завершились успешно. В настольной конфигурации выполнен 201 тест, в серверной — 125, часть сценариев общая. Готовые Linux-пакеты x64 и ARM64 проверены в QEMU, сборка macOS — в Chrome на Apple Silicon. Windows x64 и Intel-срез macOS проверены по содержимому архивов без нативного запуска.
