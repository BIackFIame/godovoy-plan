# Руководство по настольному приложению

Для календаря с обязательной связью выберите **Серверный календарь** при запуске или в разделе обмена. В офисе укажите внутренний адрес и введите личный ключ в браузере. Для работы из дома понадобится внешний адрес компании и ключ, которому администратор разрешил удалённый доступ. Оба входа открывают одни и те же задачи. Дальнейшие разделы этого руководства описывают работу с локальными копиями. [Настройка серверного режима и отзыв ключей](ONLINE.md)

Первый запуск и новый локальный календарь оставляют сетевой обмен выключенным. Чтобы пригласить коллегу, откройте «Синхронизация» и выберите «Включить обмен по локальной сети». На новом компьютере копирование запроса устройства или присоединение также включает обмен. Выбор сохраняется при перезапуске. Ранее созданные в старых версиях рабочие календари сохраняют привычный режим.



Локальный годовой календарь компании для Windows и macOS. Интерфейс, хранение, расчёт сроков и синхронизация написаны на Rust. После установки приложение работает с отключённым интернетом. Данные хранятся на компьютерах сотрудников, которые обмениваются ими напрямую.

Мобильные клиенты Android и iOS используют то же ядро Rust. Подключение по приглашению, работа без сети и сборка описаны в [мобильной инструкции](mobile/README.md).

## Начало работы

1. На первом компьютере заполните имя и название календаря, затем нажмите **Создать календарь**.
2. На компьютере коллеги откройте **Присоединиться → Скопировать запрос устройства**. Коллега отправляет вам запрос в личном сообщении и оставляет окно приложения открытым.
3. На первом компьютере откройте **Синхронизация**, вставьте запрос и нажмите **Создать и скопировать код**. Отправьте ответ тому же коллеге. Он вводит имя и вставляет код на своём компьютере. Код действует 15 минут и привязан к этому запуску приложения. После перезапуска запросите новый. Для приглашений оба компьютера должны использовать версию 0.5.41 или новее и видеть друг друга по локальной сети. Если автопоиск недоступен, раскройте **Указать сетевой адрес вручную**.
4. Нажмите **Новое событие**. Укажите ответственного и выберите даты события, начала подготовки и сроков чек-листа. Для ежегодного события включите **Повторять каждый год**.

Если после приглашения компьютер, выдавший код, выключили, другой обновлённый компьютер может ещё не знать о новичке. Подключите к нему в локальной сети компьютер, выдавший код, или уже знакомое устройство, которое успело получить новый список участников. Откройте **Синхронизация → Подключённые устройства** на компьютере, пропустившем приглашение. Когда новое устройство появится в списке, они смогут обмениваться напрямую.

Шаблон повторяющегося события создаёт отдельный чек-лист на каждый год. В редакторе можно изменить один год или шаблон с выбранного года. Результаты и заметки сохраняются в дневнике события.

## Один сотрудник на компьютере и телефоне

1. Обновите все устройства команды до версии 0.5.42 или новее. Подключите телефон к календарю обычным приглашением.
2. На устройстве, с которого управляете доступом, откройте **Синхронизация → Устройства сотрудников**. В поле **Устройство** выберите телефон, в поле **Сотрудник** — того, кому уже назначены события. Сверьте идентификаторы, если имена совпадают.
3. Нажмите **Сохранить назначение**. После следующего обмена на обоих устройствах появятся задачи сотрудника, включая ранее назначенные телефону или компьютеру. Отметки чек-листа общие, прочтение уведомления хранится на каждом устройстве отдельно.
4. Если выбрали неверное устройство, вернитесь в тот же раздел и назначьте ему **Отдельный сотрудник**. Для устройства с утерянным доступом используйте отдельную команду **Отозвать доступ**.

Календарь и напоминания работают без интернета. Изменение привязки доступно другим устройствам после обмена по локальной сети или импорта свежего файла `.yrplan`. В версиях до 0.5.42 действует прежнее правило назначения на устройство.

## Обзор и напоминания

- В **Обзоре** доступны периоды 30, 60 и 90 календарных дней, считая сегодня. По неделям сгруппированы даты начала подготовки, сроки открытых пунктов и сами события. Фильтр показывает выбранного ответственного или события без ответственного.
- В **Моих задачах** чек-лист появляется у ответственного с даты начала подготовки. В **Напоминаниях** виден старт подготовки и сроки открытых пунктов, наступающие завтра или уже наступившие. У каждого напоминания есть переход в событие и отметка о прочтении. Общий баннер открывает список.
- Прочтение хранится локально в файле `reminders-v1.json` для данного профиля. Уведомления 0.4, помеченные только по факту попытки системного показа, в 0.5 считаются непрочитанными, пока их условия действуют. Автозапуск включается в **Напоминаниях** для основного профиля и начинает действовать при следующем входе в систему. После перемещения приложения включите автозапуск из его нового расположения.
- Для обмена и системных уведомлений приложение должно работать. На время сна компьютера и выхода из учётной записи обмен останавливается. Просроченные непрочитанные напоминания остаются доступны после запуска. Системный показ зависит от настроек ОС.

## Локальная сеть и хранение

- Новый локальный календарь открывается без сетевых портов обмена. После включения обмена, создания приглашения или присоединения к коллеге приложение запоминает выбор и использует TCP 45736 для синхронизации и UDP 45737 для поиска по IPv4. Пауза освобождает оба порта. Существующие профили после обновления сохраняют прежний режим. Между подсетями и в корпоративном VPN можно указать адрес вручную. Если ОС запросит доступ к локальной сети или входящим подключениям, разрешите его для доверенной сети компании.
- Каждое устройство может работать со своей копией в автономном режиме. Когда компьютеры снова доступны друг другу, они объединяют изменения. Прогресс объединяется по отдельным пунктам. Для одновременных изменений одного пункта, одной версии события или одной заметки применяется одно и то же детерминированное правило на всех устройствах.
- Объявление о присутствии шифруется. Идентификаторы устройства и календаря в UDP доступны участникам с ключом календаря или получателю действующего приглашения. Адреса участников, время и объём трафика видны в сети. При установлении TCP-соединения начальный заголовок также содержит тип операции и идентификатор календаря или приглашения. Содержимое событий и секретные ключи в этот заголовок не входят. При смешанных версиях укажите адрес вручную, если автопоиск не нашёл коллегу. Клиенты версии 0.5.49 и старше продолжают отправлять прежние открытые объявления. При откате программы также возвращается прежнее поведение сетевого обмена.
- Состояние хранится в файле `calendar.json`. Папка по умолчанию — `%LOCALAPPDATA%\GodovoyPlan` на Windows и `~/Library/Application Support/GodovoyPlan` на macOS. Для резервной копии закройте приложение. Сохраните также `reminders-v1.json`, если нужно перенести отметки о прочтении. Восстанавливайте копию в профиле того же устройства. В календаре хранится ключ пространства. На macOS папка профиля должна быть закрыта для группы и остальных пользователей (права `0700`).
- В Windows храните профиль на локальном NTFS-диске. 0.5.41 проверяет владельца и доступ к каталогам, рабочим файлам и копиям. На macOS проверяются права и ACL. Для защиты данных при потере ноутбука включите BitLocker или FileVault. Для передачи коллеге используйте `.yrplan`. [Права профиля и восстановление](review/v0.5/PROFILE-PROTECTION.md)
- В локальной сети Noise шифрует соединение и подтверждает общий ключ календаря. Каждое допущенное устройство получает календарь команды целиком. Для персональной проверки сотрудника и ограничения доступа его задачами используйте серверный календарь с личными ключами. Версии 0.5 сверяют отпечатки внутри защищённой сессии, сжимают изменившиеся снимки и поддерживают обмен с 0.4. Лимит — 2 000 планов, включая историю удалений, и 8 МиБ для сетевого сообщения. Файл профиля дополнительно вмещает 64 КиБ служебных полей. Если объединение превысит предел, исходные копии сохранятся, а в окне «Синхронизация» появится причина отказа.

При уходе сотрудника откройте **Синхронизация → Доступ к календарю**, выберите все его устройства по ID и подтвердите **Отозвать доступ**. Первый отзыв закрепляет управление за этим компьютером. С него выдайте новые приглашения оставшимся сотрудникам. До переподключения держите прежнюю синхронизацию на паузе и вносите конфиденциальные изменения только в календарь с новым ключом. [Отзыв доступа и офлайн-изменения](review/v0.5/DEVICE-ACCESS.md)

## Сборка из исходников

Нужен Rust 1.94 или новее. Для Windows при сборке с MSVC нужны инструменты C++ и Windows SDK. На macOS нужны Xcode Command Line Tools. Cargo скачивает зависимости при первой сборке. Готовое приложение полностью локальное.

```sh
cargo build --release --locked
cargo test --locked
```

Для сборки с MSVC откройте Developer Command Prompt с доступным `rc.exe` из Windows SDK. При сборке с MinGW нужен `<архитектура>-w64-mingw32-windres` из комплекта для целевой архитектуры. Путь к компилятору ресурсов можно передать через `RC` (MSVC) или `WINDRES` (MinGW).

Исполняемый файл находится в `target/release`. Для локального запуска из исходников используйте `cargo run --locked`. Допустимые параметры — `--data-dir <папка>`, `--listen <IPv4:порт>` и `--no-discovery`.

При включённом P2P параметр `--listen` задаёт локальный IPv4-адрес для входящего и исходящего TCP. Значение `--listen 127.0.0.1:45736` ограничивает обмен этим компьютером. UDP-объявления идут только на указанный loopback-адрес. Для нескольких клиентов на одном компьютере задайте разные TCP-порты и при необходимости передайте адрес вручную. При выборе конкретного адреса сетевой карты (например, `--listen 192.168.1.20:45736`) автопоиск отключается, UDP-порт остаётся свободен. Используйте адрес из приглашения или введите его вручную. При выборе `0.0.0.0` автопоиск работает через широковещательные объявления, если разрешён настройками. Маршрут исходящего соединения с выбранным адресом источника определяет ОС.

## Системные требования

Сборки Windows выпущены для Windows 10 и новее, для x86, x64 и ARM64. Интерфейс использует драйвер OpenGL. Сборка macOS универсальная для Apple Silicon и Intel. Фактическую пригодность сборки для конкретного старого компьютера определяют ОС, драйвер и объём календаря. [Цели Rust для Windows](https://doc.rust-lang.org/rustc/platform-support.html)

## Проверка на Windows и Mac

1. Запустите приложение на Windows и Mac в одной сети или в режиме моста виртуальной машины. Интернет можно отключить, сохранив связь между компьютерами.
2. Создайте календарь и подключите второй компьютер по приглашению. Для виртуалки при необходимости введите адрес, доступный с её сетевого интерфейса.
3. Создайте ежегодное событие с двумя пунктами и дождитесь, пока оно появится на втором компьютере.
4. На обоих компьютерах включите **Приостановить обмен**. Отметьте на каждом свой пункт. Возобновите обмен и убедитесь, что на обоих экранах видны две отметки.
5. Перейдите на следующий год и проверьте, что его чек-лист пуст. Затем создайте тестовое событие со стартом подготовки сегодня и назначьте ответственного. У него должен появиться чек-лист в «Моих задачах» и напоминание.

## Интеграции

При обновлении с версий до 0.5.41 остановите старые HTTP-интеграции. После обновления включите API заново и укажите свежие ключи в комплектном `godovoy-bridge`. Клиент проверяет подлинность приложения перед передачей запроса.

В разделе **Интеграции** включается API для программ на том же компьютере. Сервер компании может отдавать данные локальному мосту `godovoy-bridge`, который запускается отдельно и подхватывает изменения по расписанию. Расширение доступно рядом с приложением в сборке. В [документации API](API.md) есть примеры, настройка для Bitrix24 и схема подключения Neactor. [OpenAPI](openapi.yaml) описывает методы и формы данных.
