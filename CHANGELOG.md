# История изменений

## 0.5.43

- Добавлен режим обязательной связи с компьютером компании. События, чек-листы, назначения и заметки доступны через браузер только при действующем ключе. На настольных и мобильных устройствах появился вход «Серверный календарь».
- Администратор может перенести календарь из автономного профиля, выдать отдельные ключи с правами чтения или редактирования и отозвать их без перезапуска службы. Для восстановления копий предусмотрен массовый отзыв ключей.
- Узел ведёт месячные журналы доступа. Опубликованы инструкция для администратора, описание API и разбор условий обработки персональных данных в России и Беларуси. [Руководство](ONLINE.md) · [API](ONLINE-API.md) · [Персональные данные](DATA-PROTECTION.md)

## 0.5.42

- Один сотрудник может получать общие задачи и личные напоминания на нескольких устройствах. Привязка явная, у однофамильцев и тёзок сохраняются раздельные назначения. Для работы достаточно локального календаря.
- Существующие события и история чек-листов сохраняются. Каждому устройству по-прежнему нужны своё приглашение и собственный доступ. Интернет для запуска и напоминаний не требуется.
- В ответах локального API добавлен `employeeId` для группировки назначений по сотруднику.

## 0.5.41

- Приглашение привязано к запросу конкретного устройства. Управляющее устройство может отозвать доступ и сменить ключ календаря.
- Добавлены мобильные клиенты и защищённый файловый обмен с настольной версией. Доступные пакеты и результаты проверки приведены в [описании выпуска](https://github.com/BIackFIame/godovoy-plan/releases/tag/v0.5.41).

## Доработки в 0.5.1

- Недоступный или повреждённый файл отметок больше не мешает открыть календарь. Если файл повреждён или вырос сверх лимита, в «Напоминаниях» можно начать отметки заново. Приложение сохраняет исходный файл рядом под именем `reminders-damaged-*.json`.
- С версии 0.5.30, если файловая система не поддерживает жёсткие ссылки, приложение сохраняет отдельную копию исходного файла отметок размером до 32 МиБ. При отказе копирования файл остаётся на месте. Если он превышает лимит, закройте приложение, переместите `reminders-v1.json` из папки профиля в безопасное место и снова откройте календарь. Будет доступен новый список отметок.
- С версии 0.5.31 календарём можно пользоваться во время восстановления отметок. При закрытии окна приложение дожидается результата. Если восстановление завершится ошибкой, окно останется открытым, а причина будет указана в разделе **Напоминания**.
- Годовой список и круг переиспользуют подготовленные строки между перерисовками. Сортировка и поиск пересчитываются при смене года, фильтра или данных профиля.

## Доработки в 0.5.2

- В «Синхронизации» видны число записей с историей удалений, размер календаря на диске и ошибки объединения. При заполнении любого предела на 90% появляется отметка рядом с пунктом синхронизации.
- Если общий календарь двух офлайн-устройств не помещается в профиль, обе копии остаются целыми. Запрос импорта, который добавляет слишком много записей, также отклоняется целиком. Обновления существующих записей доступны в пределах лимита файла.
- Чтение интерфейса, LAN-снимка и HTTP API использует последний сохранённый снимок. Записи API выполняются по очереди в отдельном рабочем потоке. [Проверки ёмкости и нагрузки](review/v0.5/CAPACITY.md)

## Доработки в 0.5.3

- «Мои задачи» строят строки только для видимой части списка. Группы событий, порядок сроков, отметки и переход к событию сохранены. Индекс открытых пунктов готовится при первом открытии страницы и обновляется после изменения календаря.
- Обзор, личные задачи и напоминания собирают события без промежуточной сортировки по каждому году. Итоговый порядок по датам сохранён. [Замер и проверка длинного списка](review/v0.5/TASKS.md)

## Доработки в 0.5.4

- При первом запуске сразу видны два пути: создать календарь или присоединиться по коду от коллеги.
- Даты события, начала подготовки и пунктов чек-листа выбираются в календаре. У нового события можно включить ежегодный повтор. Перед закрытием изменённого черновика приложение запрашивает подтверждение.
- `⌘N` / `Ctrl+N` открывает редактор, `⌘F` / `Ctrl+F` переводит фокус в поиск, `⌘Enter` / `Ctrl+Enter` сохраняет событие. [Проверка интерфейса](review/v0.5/UX.md)

## Доработки в 0.5.5

- Если календарь занят или файл профиля недоступен, приложение показывает причину и путь к папке. Когда другой экземпляр закрыт или резервная копия восстановлена, нажмите **Повторить попытку**. При повторной попытке после повреждения исходный календарь можно сохранить отдельно, а приложение дождётся файла из копии. [Проверка восстановления](review/v0.5/RECOVERY.md)

## Резервные копии в 0.5.6

В **Календаре** откройте **Резервные копии** и нажмите **Создать копию**. Для хранения на другом диске скопируйте папку `backups` целиком, включая `origin.json`. Копии предназначены для восстановления профиля того же устройства. В них хранится ключ команды, поэтому ограничьте доступ к папке.

**Восстановить из копии** доступно в календаре и в окне ошибки запуска. Если копия лежит на другом диске, верните папку `backups` в папку профиля перед выбором. Приложение сохраняет предыдущий `calendar.json` отдельно и открывает календарь с синхронизацией на паузе. Когда возобновите обмен, более свежие правки коллег могут вернуться. [Проверка резервных копий](review/v0.5/BACKUPS.md)

После восстановления **Вернуть прежний календарь…** открывает подтверждение для сохранённой точки возврата, если она есть. В разделе **Исходные файлы восстановления** находятся файлы профиля, в которых могут остаться ключ команды и токены API. Для передачи данных коллегам используйте зашифрованный `.yrplan` в разделе **Синхронизация**.

## Напоминания и автозапуск в 0.5.7

В разделе **Напоминания** нажмите **Проверить уведомления**. На macOS это действие может запросить разрешение системы. Неудачная отправка обычного напоминания повторяется автоматически. Прочтение по-прежнему отмечается в приложении.

С версии 0.5.33 системное уведомление предлагает открыть «Напоминания». Названия событий, пункты и даты видны внутри приложения. Открытие события из списка происходит сразу. Отметки о прочтении сохраняются в фоне, а новые сроки появляются как отдельные напоминания.

Если приложение переместили после настройки автозапуска, в **Напоминаниях** можно обновить путь или отключить автозапуск. При уже открытом профиле повторный запуск при входе завершается тихо. [Проверка уведомлений и автозапуска](review/v0.5/NOTIFICATIONS.md)

## Синхронизация в 0.5.8

После успешного входящего обмена одно из устройств временно уступает инициативу другому. Правки обеих сторон передаются за один сеанс. Если входящий обмен прекращается, устройство снова подключается само. [Нагрузочная проверка синхронизации](review/v0.5/LAN-PILOT.md)

## Приём календаря в 0.5.9

Принятый по сети сжатый календарь распаковывается по кадрам. Объём буферов приёма ограничен двумя кадрами. Проверки длины, целостности сжатого потока и контрольной суммы сохраняются. [Проверка транспорта](review/v0.5/LAN-STREAM.md)

## Память при сохранении в 0.5.10

Временные снимки календаря разделяют неизменённые события и их чек-листы. Сохранение по-прежнему публикует новый снимок атомарно. Формат профиля и сетевой обмен совместимы с предыдущими версиями. [Замеры памяти](review/v0.5/LAN-MEMORY.md)

## Память интерфейса в 0.5.11

После смены данных кэш «Обзора» позволяет сразу освободить старый снимок календаря, даже когда открыт другой экран. При возврате в «Обзор» приложение строит сроки по последнему сохранённому календарю. [Проверка в окне macOS](review/v0.5/GUI-MEMORY.md)

## Пауза синхронизации в 0.5.12

Пауза обмена с коллегами сохраняется в локальном профиле после восстановления из копии и при включении вручную. Она действует при следующих запусках. Чтобы возобновить обмен, в **Синхронизации** снимите флажок **Приостановить обмен**. [Проверка восстановления](review/v0.5/BACKUPS.md)

## Ошибка восстановления в 0.5.13

Если выбранную копию не удалось применить, открытый календарь и его локальный API продолжают работать. Сообщение в окне восстановления указывает на выбранную копию, а **Отмена** возвращает к открытому календарю. [Проверка ошибочной и исправной копий](review/v0.5/BACKUPS.md)

## Восстановление после аварийного завершения в 0.5.14

Если файл уже созданной команды пропал, приложение открывает экран восстановления. При открытии исправного календаря программа убирает промежуточные файлы своих прерванных записей. Для профилей прежних версий признак существующей команды сохраняется при первом успешном открытии в 0.5.14. [Проверка аварийного завершения](review/v0.5/BACKUPS.md)

## Черновики и мост Bitrix24 в 0.5.15

- При закрытии окна с изменениями в событии или дневнике приложение предлагает продолжить работу или выйти без сохранения. Проверяется и черновик заметки после перехода к другому событию. [Проверка закрытия окна](review/v0.5/UX.md)
- При работе моста Bitrix24 без заданного диапазона год определяется заново на каждом проходе. Границы, заданные при запуске, фиксируют диапазон. [Параметры импорта](API.md)

## Автопоиск и конфликт дневника в 0.5.16

- При быстрой смене порта автопоиск обновляет объявление этого устройства на том же IPv4. [Проверка переподключения](review/v0.5/LAN-PILOT.md)
- При конфликте дневник показывает сохранённый текст и ваш черновик. Можно заменить черновик или объединить тексты вручную. Если коллега снова изменит запись, приложение предложит ещё раз сравнить варианты. [Проверка дневника](review/v0.5/UX.md)

## Устаревший адрес в приглашении в 0.5.17

При автоматическом подключении приложение может перейти к свежему адресу из автопоиска, если старый адрес устройства принимает соединение и затягивает рукопожатие. Единственному адресу остаётся полное время ожидания. Получение календаря после проверки ключа имеет отдельный срок. [Проверка подключения](review/v0.5/LAN-PILOT.md)

## Командная просрочка и сетевые маршруты в 0.5.18

- В **Обзоре → Просрочено** видны невыполненные пункты со сроком от 90 дней назад до вчера. Фильтр ответственного общий с режимом **Ближайшие**. [Проверка интерфейса](review/v0.5/UX.md)
- Последний адрес устройства после успешного защищённого обмена сохраняется отдельно от прежнего списка адресов. Его можно использовать после перезапуска при выключенном автопоиске. [Проверка при заполненном списке](review/v0.5/LAN-PILOT.md)

## Восстановление черновиков и удаление адресов в 0.5.19

- Черновики события и дневника сохраняются в `drafts-v1.json` внутри профиля. После запуска приложение открывает восстановленный редактор или последнюю доступную заметку. При закрытии окна можно продолжить работу, выйти с черновиками или явно удалить их. [Проверка черновиков](review/v0.5/UX.md)
- В **Синхронизации → Подключение по адресу и состояние сети** можно удалить устаревшую запись из сохранённого списка. Это освобождает место для ручного адреса. [Проверка адресов](review/v0.5/LAN-PILOT.md)

## Список черновиков в 0.5.20

- Раздел **Черновики заметок** показывает текущие и отложенные записи. Из списка можно открыть событие нужного года, скопировать текст или удалить выбранный черновик. Проверка фоновой записи сравнивает неизменившиеся черновики без копирования. [Нативный прогон и замеры](review/v0.5/UX.md)
- Если сохранение сетевого маршрута временно не удалось, приложение повторяет попытку при следующем обмене после короткой паузы. [Проверка маршрута](review/v0.5/LAN-PILOT.md)

## Событие по образцу в 0.5.21

- В карточке события нажмите **Создать по образцу**. Откроется черновик с полями выбранного года и сроками чек-листа. У нового события свой дневник и свои отметки выполнения.
- Если коллега изменил или удалил событие, пока ваш черновик был открыт, нажмите **Сохранить как новое**. Приложение перенесёт введённые данные в новый черновик. Проверьте дату и нажмите **Создать событие**.
- В macOS приложение переходит на совместимый протокол, если при первом подключении к старой версии она сбрасывает пробное соединение. [Проверка совместимости](review/v0.5/LAN-PILOT.md)

## Мои задачи и резервные копии в 0.5.22

- В **Моих задачах** переключатели **Сегодня и завтра** и **Просрочено** оставляют открытые пункты с соответствующими сроками. Пункт январского события может появиться в декабре.
- Если локальный обмен не запустился, верхняя кнопка показывает **Синхронизация · сбой** и открывает подробности.
- В **Резервных копиях** видна дата последнего файла. Если при работающем приложении текущий файл исчез или повреждён, восстановление дополнительно сохраняет открытый календарь и показывает путь к нему. [Проверка резервных копий](review/v0.5/BACKUPS.md)

Когда интеграция переносит одноразовое событие в другой год, его дневник и отметки доступны с новой даты. Изменения коллег, внесённые офлайн до переноса, учитываются после обмена. Обновите все рабочие места для одинакового отображения. [Правила импорта](API.md#правила-обновления)

Старую копию размером 8 МиБ можно восстановить с сохранением текущих настроек. При сбое записи паузы обмен всё равно приостанавливается до закрытия приложения. [Проверка пределов](review/v0.5/CAPACITY.md)

## Возврат к прежнему календарю в 0.5.27

Чтобы вернуться к состоянию до восстановления, откройте **Резервные копии → Восстановить из копии** и выберите запись **Точка возврата** (до 0.5.35 — **Перед восстановлением**). Приложение сохраняет прежний календарь и при обратной операции. Если запись точки недоступна, окно сообщает, где сохранены прежние данные. [Проверка резервных копий](review/v0.5/BACKUPS.md)

## Обмен без сети и по кабелю в 0.5.28

**Синхронизация → Обмен через файл** создаёт зашифрованный файл `.yrplan`. Передайте его через флешку, AirDrop между Mac или системную передачу файлов Bluetooth на совместимых устройствах. Коллега открывает файл в том же разделе. Приложение объединяет календари, включая изменения, сделанные офлайн с обеих сторон. Для обратного обмена второй компьютер сохраняет свой файл. У обоих сотрудников уже должно быть подключено одно пространство.

Для прямого **Ethernet** или **Thunderbolt Bridge** между Mac используйте существующую IP-синхронизацию. Соедините компьютеры, убедитесь, что у обоих есть IPv4 на кабельном интерфейсе, и введите адрес коллеги в **Синхронизация → Подключение по адресу и состояние сети**. Если автопоиск выбирает другой интерфейс, запустите один экземпляр с `--listen <IPv4 кабеля>:45736` и укажите этот адрес на втором. При отсутствии DHCP можно назначить в свободной подсети, например, `192.168.77.10` и `192.168.77.11` с маской `255.255.255.0`. Шлюз для прямого обмена не требуется. USB-C подключается этим способом, если система видит соединение как сетевой интерфейс. [Ethernet на Mac](https://support.apple.com/guide/mac-help/use-ethernet-to-connect-two-mac-computers-mchlp1413/mac) · [IP через Thunderbolt](https://support.apple.com/en-by/guide/mac-help/mchld53dd2f5/mac)

В AirDrop и системной передаче Bluetooth отправляется готовый файл. Эти способы работают при поддержке соответствующей функции на обоих устройствах. [AirDrop на Mac](https://support.apple.com/guide/mac-help/mh35868/mac) · [Передача файлов по Bluetooth в Windows](https://support.microsoft.com/en-us/windows/hardware/bluetooth/send-and-receive-files-over-bluetooth-in-windows)

Начиная с 0.5.29 при закрытии окна приложение дожидается окончания текущего файлового обмена. Если операция завершится ошибкой, окно останется открытым и покажет причину. Если при записи на флешку прервался экспорт и приложение сообщило о неполном файле, удалите его или повторите сохранение под другим именем.

## Календарь и результат восстановления в 0.5.35

- Выбранное событие выделяется в списке и на годовом круге. Счётчик непрочитанных находится в разделе **Напоминания**.
- После восстановления нажмите **Готово**, чтобы продолжить работу с календарём, или **Вернуть прежний календарь…**, чтобы открыть подтверждение возврата. Синхронизацию можно возобновить в разделе **Синхронизация**.

## Восстановление в 0.5.36

После подтверждения видно состояние **Восстанавливаем календарь**. Если закрыть окно во время записи, приложение дождётся её завершения. Кнопка **Остаться в приложении** отменяет закрытие. При ошибке окно остаётся открытым и показывает причину.

## Создание резервной копии в 0.5.37

Копия сохраняет календарь на момент начала операции. Пока она записывается, можно закрыть диалог и продолжить работу. Результат появится внизу окна. Если закрыть приложение, оно дождётся записи. При ошибке приложение останется открытым, а подробности будут в **Резервных копиях**.

## Календарь и задачи в 0.5.38

В центре круга показаны месяц выбранного события и число событий этого месяца с учётом фильтров. Если даты расположены близко, нажмите число на дуге месяца, чтобы выбрать событие из списка. В боковой панели календаря и в **Моих задачах** срок виден под названием пункта. Метки **Сегодня** и **Просрочено** помогают определить, за что взяться в первую очередь.
