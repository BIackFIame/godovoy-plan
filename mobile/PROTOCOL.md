# Контракт мобильных клиентов

`gp_open(path)` открывает один приватный каталог профиля в контейнере приложения. Нулевой указатель означает отказ открытия. Клиент последовательно вызывает `gp_request(handle,json)` вне главного потока. Возвращённая UTF-8 строка принадлежит Rust до `gp_string_free`. После завершения всех запросов клиент может вызвать `gp_close` один раз.

Каждый ответ имеет форму `{"ok":true,"data":...}` или `{"ok":false,"error":"сообщение"}`. Пустой успешный результат содержит `data:null`. Идентификаторы передаются строками UUID, даты в виде `YYYY-MM-DD`. Строковые значения из календаря отображаются как текст. Все команды используют поле `op`.

| op | Дополнительные входные поля | data |
|---|---|---|
| state | year (число) | `{deviceId,employeeId,workspaceName,year,members,employees,events,tasks,reminders,lanEnabled,paused,lastSync}`. `workspaceName` и `lastSync` могут быть null. `members` — `{id,name,revoked,employeeId}[]`. `events` — события выбранного года. `tasks` — события текущего пользователя, которым требуется внимание сегодня. `reminders` — `{eventId,year,title,date}[]`. |
| createWorkspace | name, employee | null |
| createEvent | title, date, yearly (bool), preparationDays (число), ownerId (UUID или null), category (`Campaign`, `Partners`, `Team`, `Operations`), checklist (`{title,daysBefore}[]`), description (строка, опционально) | null |
| check | eventId, year, taskId, done (bool) | null |
| note | eventId, year, text | null |
| pairingRequest | | строка для передачи коллеге |
| invite | request (запрос устройства) | строка приглашения |
| join | code, employee, address (строка IPv4:порт или null) | null |
| rejoin | code, address (строка или null) | null |
| peer | address (строка IPv4:порт) | null |
| pause | paused (bool) | null |
| export | | абсолютный путь к зашифрованному `.yrplan` в приватном временном хранилище |
| import | path (путь к частной копии, созданной системным выбором файла) | null |

Событие в `events` и `tasks` имеет поля `id`, `year`, `title`, `date`, `yearly`, `category`, `ownerId` (или null), `preparationDate`, `note`, `description`, `checklist`. Элемент `checklist` содержит `id`, `title`, `dueDate`, `done`. Для показа даты начала подготовки персональных задач и открытия напоминания используется год самого события.

Для редактирования и удаления передайте `op` равным `editEvent` или `deleteEvent`, а также `eventId`, `year`, `revision` из отображённого события и `scope` (`year` для выбранного года, `future` для шаблона с этого года). `editEvent` также принимает все поля события как в `createEvent`, включая строку `description`. Существующим пунктам передаются исходные `id`, новым — только `title` и `daysBefore`. После параллельного изменения шаблона требуется заново прочитать событие. Снимки событий также содержат `preparationDays`, `revision` и `daysBefore` каждого пункта. При сохранении заметки можно передать `base` с прочитанным ранее текстом.

`state.notificationDates` содержит уникальные даты для личных напоминаний на следующие 60 календарных дней, включая сегодняшний. План включает старт подготовки и открытые пункты за день до срока и в сам срок. Уведомление на экране блокировки содержит только приглашение открыть приложение. Список обновляется при очередном открытии и синхронизации приложения.

## Управление доступом и жизненный цикл

| op | Входные поля | Действие |
|---|---|---|
| linkEmployeeDevice | deviceId, employeeId (UUID) | Связать назначения устройства с сотрудником. Для отдельного списка передайте ID самого устройства в обоих полях. |
| revoke | deviceIds (массив UUID) | Отозвать перечисленные устройства и перейти к новому поколению ключа |
| renew | | Обновить ключ доступа |
| background | | Приостановить обмен при уходе приложения в фон |
| foreground | | Восстановить предыдущее состояние сетевого обмена |

Состояние также возвращает `canManage`, `accessManagerId`, `address`, `networkError` и `notificationDates`. Адрес, ошибка сети и ID управляющего устройства могут быть null. При импорте системный клиент копирует выбранный файл в `<профиль>/exchange/<UUID>.yrplan`, передаёт абсолютный путь и удаляет временную копию по окончании. Размер входного файла ограничен 9 МиБ.

Фоновый опрос открытого экрана может передать в `state` поле `ifToken` со значением `stateToken` из последнего полного ответа. Если год, дата, данные профиля, квитанции напоминаний и сетевое состояние совпадают, ядро вернёт только `{"unchanged":true}`. По умолчанию изменение приводит к полному снимку. После нового запуска запросите полный снимок.

После неудачного `gp_open` вызовите `gp_open_error()` на том же нативном потоке, чтобы получить локальное сообщение об ошибке. Скопируйте текст и передайте указатель в `gp_string_free`. После успешного открытия функция возвращает нулевой указатель.


## Сотрудники и устройства

Поле `deviceId` обозначает устройство для сетевого доступа и отзыва. Поле `employeeId` в состоянии показывает, чьи задачи и напоминания отображаются на этом устройстве. До подключения к календарю оно равно null. В `members` перечислены устройства, в `employees` — доступные для новых назначений сотрудники в формате `{id,name}`. Каждому сотруднику соответствует хотя бы одно устройство с действующим доступом. Имя сотрудника может совпадать с именем другого сотрудника.

У события `ownerId` хранит исходное назначение, а `employeeId` обозначает сотрудника после применения связей. Для нового назначения выбирайте ID из `employees`. Если ответственный в форме редактирования остался прежним, отправляйте исходный `ownerId`. У каждого события и каждой годовой записи сохраняются собственные идентификаторы, отметки и история.

Команда `linkEmployeeDevice` доступна устройству с правом управления. Список `deviceIds` в команде `revoke` всегда содержит конкретные устройства. После отзыва одного устройства назначения по-прежнему видны на остальных устройствах сотрудника с действующим ключом.

`lanEnabled` показывает сохранённый выбор локального обмена на этом устройстве. Новый профиль и новый локальный календарь запускаются без слушателей TCP/UDP. Команды `pairingRequest`, `join`, `rejoin`, `invite`, `peer` и `pause` с `paused=false` выражают явный выбор обмена. Команды чтения и жизненного цикла сами по себе этот выбор не меняют.

### Изменение времени последнего обмена

Актуальное ядро указывает `supportsSyncStamp: true` в полном снимке. После этого клиент может передать в запросе `state` выбранный `year`, сохранённый `ifToken` и `acceptSyncStamp: true`. Если со времени этой версии изменилось только отображаемое время обмена, ответ содержит `syncStamp: true`, `year`, `baseToken`, `stateToken` и обязательное поле `lastSync`. Значение `lastSync` — строка RFC 3339 или `null`. Новый токен действует для следующего опроса.

Сверьте год и исходный токен с запросом и с **текущим открытым снимком**, затем одновременно замените `lastSync` и `stateToken`. Остальные поля сохраняются. Просроченный ответ от другого запроса или года пропускается. При несовместимой форме ответа запросите один полный `state` без условных полей. Ошибки доступа и открытия профиля обрабатываются обычным путём с очисткой экрана.

Клиент отправляет `acceptSyncStamp` только после объявления возможности. Старые ядра отклоняют неизвестные поля запроса. Клиенты, которые передают только `ifToken`, продолжают получать полный снимок при изменении времени обмена. Полный ответ также возвращается при смене календарного дня, года, данных профиля, квитанций напоминаний или отображаемого сетевого состояния.
