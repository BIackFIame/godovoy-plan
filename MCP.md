# Подключение ИИ к личным задачам

Сотрудник может спросить у помощника «К каким событиям мне готовиться в следующем месяце?» или попросить отметить сделанный пункт чек-листа. Для подключения нужен сервер «Годового плана» версии 0.5.47 или новее и клиент с транспортом **Streamable HTTP** и заголовком **Authorization**. Обмен идёт через обычный офисный или удалённый вход календаря.

## Выдать доступ

В локальной панели ИТ откройте **Сотрудники**, выберите человека и в разделе **Подключение ИИ по MCP** нажмите **Выдать ключ помощника**. По умолчанию помощник получит доступ для чтения в офисе. Если ему нужны запись или внешний вход, при выдаче выберите соответствующее разрешение. Для выдачи требуется один действующий обычный ключ этого же человека с полномочиями, достаточными для всех выбранных разрешений. Передайте сотруднику показанный один раз секрет через принятый в компании защищённый канал.

Для выдачи через командную строку на основном сервере администратор находит сотрудника в выводе `status`. Имя и UUID в команде выдачи должны принадлежать одному человеку. Для каждого клиента этого сотрудника можно выдать отдельный ключ.

```text
godovoy-online status team-calendar
godovoy-online grant team-calendar "Анна Иванова" --employee-id UUID_АННЫ --mcp
```

Этого ключа достаточно, чтобы читать события Анны. Для клиента, которому разрешено отмечать пункты чек-листа и вести дневник, администратор выдаёт ключ с явным правом записи.

```text
godovoy-online grant team-calendar "Анна Иванова" --employee-id UUID_АННЫ --mcp --mcp-write
```

Оба варианта дают доступ в пределах назначений Анны, даже если её браузерный ключ открывает весь календарь команды. Для внешнего адреса требуется также флаг `--allow-remote` и разрешение удалённого входа в действующем профиле защиты. Когда администратор закрывает внешний вход, офисный адрес продолжает работать по локальной сети. [Настройка офисного и внешнего входов](ONLINE.md)

## Подключить клиент

Заполните поля подключения в настройках MCP-клиента.

| Параметр | Значение |
|---|---|
| Транспорт | Streamable HTTP |
| Адрес | `https://plan.office.example/mcp` — замените имя на корпоративный HTTPS-адрес. Для теста на самом сервере подойдёт `http://127.0.0.1:45838/mcp`. |
| Заголовок | `Authorization: Bearer <персональный MCP-ключ>` |
| Хранение ключа | В персональном хранилище секретов клиента. Вводите ключ в поле секретов, отдельно от переписки с моделью. |

Для VS Code с подключениями MCP под управлением редактора можно использовать пользовательский `mcp.json`. В этом примере редактор спросит значение ключа при подключении. Синтаксис `inputs` относится к формату VS Code. В другом клиенте выберите его собственный способ хранения секрета. [Формат конфигурации VS Code](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)

```json
{
  "servers": {
    "godovoy-plan": {
      "type": "http",
      "url": "https://plan.office.example/mcp",
      "headers": {
        "Authorization": "Bearer ${input:godovoy-key}"
      }
    }
  },
  "inputs": [
    {
      "type": "promptString",
      "id": "godovoy-key",
      "description": "Персональный MCP-ключ календаря",
      "password": true
    }
  ]
}
```

С рабочего места сотрудника запросите «Покажи мои события на 2027 год». Перед первой записью откройте в клиенте состав вызова, сверьте событие и год. Разрешение вызовов с изменениями задаётся в клиенте. В общей установке ИИ у каждого вошедшего пользователя должен быть собственный секрет и отдельная история диалога. Сервер определяет сотрудника по предъявленному ключу.

## Что доступно помощнику

| Инструмент | Аргументы | Результат |
|---|---|---|
| `list_my_events` | `year`, необязательные `offset` и `limit` | Страница назначенных событий указанного года. Следующий `offset` возвращается в `nextOffset`, в конце — `null`. |
| `get_my_event` | `eventId`, `year` | Собственное событие с датой подготовки, чек-листом и разрешёнными текстовыми полями. |
| `set_my_task_done` | `eventId`, `year`, `taskId`, `done` | Установить или снять отметку своего пункта. Требуется право записи. |
| `set_my_note` | `eventId`, `year`, `base`, `text` | Изменить дневник своего события. Передайте в `base` последний прочитанный текст. При конфликте перечитайте запись и согласуйте изменение. Требуются право записи и разрешение свободного текста. |

Сервер проверяет ответственного за конкретный год при каждом запросе. После переназначения старая переписка может содержать ID события, но следующий вызов с прежним ключом уже получит отказ. Создание, удаление и переназначение событий, чтение справочника коллег и администрирование через этот интерфейс закрыты. При запрете свободного текста сервер скрывает ранее сохранённые описания и заметки.

Корпоративный сервер отдаёт результат MCP-клиенту. Если клиент использует облачную модель, данные могут покинуть сеть компании и сохраниться в истории провайдера. Для замкнутой локальной установки используйте локальные клиент и модель, с утверждённым доступом только к офисному адресу. У прямого P2P-профиля отдельное хранилище. Подключение MCP работает с серверным календарём. [Профили защиты и границы применения](DATA-PROTECTION.md)

## Отключить помощника

В карточке сотрудника выберите ключ конкретного помощника и отзовите его. Команда ниже делает то же по ID, показанному при выдаче.

```text
godovoy-online revoke team-calendar UUID_КЛЮЧА_MCP
```

Если отозвать обычный ключ, на основании которого выдали доступ, одновременно отзываются все привязанные к нему ключи помощников. Последующая выдача сотруднику нового обычного ключа требует новой выдачи MCP-доступа. Для проверки привязки используйте `godovoy-online status team-calendar`.

При увольнении используйте «Отозвать все ключи сотрудника» в локальной консоли ИТ. Следующий запрос придётся авторизовать действующим ключом. Отзыв действует на новые обращения к календарю. С ранее переданными результатами и историей диалогов работает администратор ИИ-клиента по правилам организации.

## Для разработчиков интеграций

Интерфейс принимает одиночные сообщения JSON-RPC 2.0 методом `POST /mcp`. Используйте `Content-Type: application/json`, `Accept: application/json, text/event-stream` и персональный Bearer-ключ. Ответ на вызов приходит в том же HTTP-запросе. Для перечисления инструментов используйте `tools/list`, для вызова — `tools/call`.

- **MCP 2026-07-28.** Клиент может сразу запросить инструменты или вызвать `server/discover`, чтобы узнать возможности сервера. В каждом запросе передавайте в `params._meta` поля `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientInfo` и `io.modelcontextprotocol/clientCapabilities`. Заголовки `MCP-Protocol-Version` и `Mcp-Method` должны совпадать с версией и методом в теле. Для `tools/call` добавьте `Mcp-Name` с именем инструмента. [MCP 2026-07-28 и обязательные заголовки](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)
- **MCP 2025-11-25.** Начните с `initialize`, укажите ревизию `2025-11-25`, затем отправьте `notifications/initialized`. В последующих запросах передавайте согласованную версию в `MCP-Protocol-Version`. Для проверки связи есть `ping`. [MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

Пример тела запроса для ревизии 2026-07-28. Вместе с ним отправьте заголовки `MCP-Protocol-Version: 2026-07-28`, `Mcp-Method: tools/call` и `Mcp-Name: list_my_events`.

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "list_my_events",
    "arguments": {"year": 2027},
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientInfo": {"name": "office-assistant", "version": "1.0"},
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}
```

Читайте поля результата из `result.structuredContent`. Для клиентов с текстовым выводом тот же результат доступен в `result.content`. Обрабатывайте как ошибки JSON-RPC, так и `result.isError` и HTTP-отказы. При HTTP 429 повторите запрос после интервала из `Retry-After`. При 401 проверьте назначение, действительность и отзыв ключа. При 403 проверьте область входа и политику организации. Отдельные клиенты кэшируют список инструментов. После изменения прав запросите его снова. [Инструменты MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
