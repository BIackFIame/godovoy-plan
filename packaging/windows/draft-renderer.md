# Резерв для одной полной проверки Windows

Используйте существующий windows-packages.yml в QA-ветке с этим изменением. Один запуск с architecture=all и scope=full проверит x86, x64 и ARM64. Архивы из рабочего каталога mesa-local-fallback содержат собранный на macOS программный драйвер. Принять его для выбранного приложения можно после прохождения Windows-теста. Для черновика укажите точный тег, числовой ID и полный исходный SHA продукта. workflow отдельно привязывает исполняемый QA-код к github.sha.

## Подготовка двух временных файлов

Сверьте SHA-256 каждого ZIP с таблицей. Извлечение в одноразовую папку можно заранее проверить на компьютере сборки функцией install из draft-renderer.py. В обоих архивах лежат opengl32.dll, libgallium_wgl.dll, внутренние контрольные суммы и лицензии.

| Имя актива черновика | SHA-256 |
|---|---|
| Mesa-26.3.1-Softpipe-Windows-x86-local-QA.zip | b99a5301076b85c6ddd1f7902d0829d6c18db310f2943640199fd91571acf455 |
| Mesa-26.3.1-Softpipe-Windows-x64-local-QA.zip | 6052db4fcde9cdcc6baf70d6ab81255264b8b6180398214652d5b91fbb0147c7 |

Оператор выпуска добавляет оба файла к тому же финальному черновику, в котором уже находятся четыре проверяемых архива Windows. Используйте точные имена и исходные файлы без переупаковки. При возобновлении незавершённой загрузки сначала сравните digest уже существующего актива. При несовпадении остановите подготовку и проверьте происхождение актива.

## Полная матрица

При разрешённом запуске выберите существующую QA-ветку с проверенным коммитом. Введите tag, draft_id и source_sha. Установите draft_renderer_pair=true, architecture=all, scope=full. Оставьте renderer_run и renderer_commit пустыми для штатной сборки ARM64 из закреплённых исходников в этом же запуске. Либо укажите ID полностью успешного запуска этого же workflow вместе с полным SHA его QA-коммита, если он содержит готовый artifact software-opengl-ARM64. Если ранее упал другой job и статус всего запуска failure, выберите штатную сборку ARM64. Для черновика и QA-коммита используются их собственные SHA.

Linux job проверит состояние draft, тег, SHA продукта и digests временных архивов перед передачей Windows VM. Только этот job имеет contents: write для чтения приватного черновика и выполняет фиксированные API-запросы чтения. На Windows выданы actions: read для загрузки артефактов. На x86 и x64 до запуска извлекаются исключительно две библиотеки, проверяются SHA-256 архива и DLL, сигнатуры и архитектура PE. Режим profile не подходит для зачёта.

Во всех трёх логах нужны успешные создание/чтение серверного календаря и отзыв доступа на отдельном NTFS-томе и в обычном LocalAppData, открытие формы подключения, возврат к созданию нового календаря, подтверждение обоих загруженных DLL из каталога приложения и штатное закрытие окна. x64 дополнительно проверяет отдельный серверный ZIP. При ошибке сохраните номер запуска, точные SHA, архитектуру и отказавший шаг.

## Завершение до публикации

Оператор выпуска удаляет из всё ещё закрытого черновика строго два QA-файла по числовым ID активов после проверки каждого digest. Если тест нужно возобновить, оба временных ZIP должны снова присутствовать в том же черновике. Перед публикацией повторно прочитайте метаданные по draft_id и сверьте, что оба имени отсутствуют, а все штатные активы и итоговая ведомость контрольных сумм совпадают с выпускным набором. Временные архивы в ведомость выпуска не включаются.

Пример для оператора с gh и jq. Установите REPO, DRAFT_ID, TAG и SOURCE_SHA из зафиксированных параметров релиза. Первый запрос только читает черновик и выводит ID двух временных активов вместе с проверенными хешами.

```bash
set -euo pipefail
api="repos/$REPO/releases"
metadata=$(gh api "$api/$DRAFT_ID")
jq -e --arg tag "$TAG" --arg sha "$SOURCE_SHA" \
  '.draft and .target_commitish == $sha and .tag_name == $tag' <<< "$metadata" >/dev/null
for arch in x86 x64; do
  name="Mesa-26.3.1-Softpipe-Windows-$arch-local-QA.zip"
  if [[ "$arch" == x86 ]]; then
    sha=b99a5301076b85c6ddd1f7902d0829d6c18db310f2943640199fd91571acf455
  else
    sha=6052db4fcde9cdcc6baf70d6ab81255264b8b6180398214652d5b91fbb0147c7
  fi
  jq -er --arg n "$name" --arg h "sha256:$sha" \
    '[.assets[] | select(.name == $n)] | select(length == 1) | .[0]
     | select(.state == "uploaded" and .digest == $h) | [.id,.name,.digest] | @tsv' <<< "$metadata"
done
```

После проверки Windows и подтверждения удаления выполните для каждого из этих двух ID команду `gh api -X DELETE "$api/assets/$ASSET_ID"`. Затем обязательно проверьте актуальные метаданные. Следующая команда завершится ошибкой, если черновик сменился или временный актив всё ещё присутствует.

```bash
gh api "$api/$DRAFT_ID" | jq -e --arg tag "$TAG" --arg sha "$SOURCE_SHA" '
  .draft and .tag_name == $tag and .target_commitish == $sha and
  all(.assets[]; .name != "Mesa-26.3.1-Softpipe-Windows-x86-local-QA.zip" and
                 .name != "Mesa-26.3.1-Softpipe-Windows-x64-local-QA.zip")' >/dev/null
```
